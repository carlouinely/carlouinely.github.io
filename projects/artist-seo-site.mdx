## A portfolio search engines could not read

An artist needs to be found before they can be booked, and a portfolio that
search engines cannot read does not help. The site had to be built around
discoverability from the first wireframe, not retrofitted with keywords after
launch.

Working with **DEVGO Studio**, I took the project from concept through to launch:
structure, content, and the search work that turns a portfolio into an entry
point for the artist's audience.

## Structure before keyword lists

Search visibility is mostly decided before any copy gets written. Pages were
planned around the things the artist wants to be found for, so each one answers a
real query instead of repeating a list of terms. The markup carries that
structure, and metadata is generated from the content instead of maintained
separately.

## Content the artist can keep

A site that only ranks while someone maintains it by hand does not stay ranked.
Content is authored as structured pages, so adding a new work or exhibition
extends pages that are already indexed instead of creating a new format to keep
alive.

The site is built with Astro and TypeScript: static pages that load quickly,
which matters both to visitors and to how the site ranks.

## The outcome

The artist's work is discoverable from the searches their audience actually
makes, and the site went from concept to launch with its structure and content
built for that from the start.
